PDD Cross-border Documents

拼多多跨境单
唛头 / 入库单生成

适用场景

当用户需要制作或修改以下资料时使用本 Skill：

  • 拼多多跨境订单的唛头（Shipping Mark）或入库单 / 入仓单
  • 装箱标签、仓库识别码标签，或涉及仓库编码、箱号、总箱数的订单资料
  • 把订单信息按固定字段填入 Word 模板并批量出单

核心规则

  1. 一个订单只对应一个 SKU 和一个品名，货品明细固定为单行。
  2. 仓库地址和仓库编码按订单填写，不得假定所有订单共用同一仓库。
  3. 唛头只生成一个文件。多箱时，在同一文件内按箱号分段，段间插入分页符，方便打印和裁剪。
  4. 入库单只生成一个文件。
  5. 9 个字段全部必填；缺字段时报错，不猜测或补造信息。
  6. 字段值可能含 &、<、> 等字符；脚本会进行 XML 转义，应通过脚本生成，不要手工改 XML。

方式一：命令行生成 DOCX

脚本使用 Python 标准库，不需要安装第三方依赖。先准备一个 UTF-8 文本文件，每行填写一个“字段：值”。

仓库地址：广东省东莞市谢岗镇粤海大道212号4栋二楼
仓库编码：DX-9A4-EG2BNM4T#
订单号：260827-684636311940992
收件人：ben
联系电话：021-53395199
总箱数：3
总数量：9
SKU：AUX-NDY-EF603RA
品名：无叶风扇

用文本文件

python scripts/pdd_docs.py fill --input order.txt --outdir ./输出

或直接传 JSON

python scripts/pdd_docs.py fill \
  --json '{"仓库地址":"...","仓库编码":"...","订单号":"...","收件人":"...","联系电话":"...","总箱数":"3","总数量":"9","SKU":"...","品名":"..."}' \
  --outdir ./输出
生成结果：入库单_{订单号}.docx 一份；唛头_{订单号}.docx 一份。唛头按箱号 01…NN 分段，多箱时每段之间分页。

方式二：构建离线 HTML 看板

看板面向非技术同事。它把 JSZip 和两份模板嵌入单个 HTML 文件，双击即可离线使用。填写 9 个字段后点击“生成并下载”，浏览器会下载两份 DOCX。

python scripts/build_kanban.py --out 跨境单看板.html
隐私说明：看板在浏览器本地处理订单信息，不会将订单信息发送到服务器。需要在线分享时，可将输出目录交给 cloudstudio-deploy 技能 / workbuddy_cloudstudio_deploy 工具部署为静态站。

模板更新后，重新运行构建命令生成新的 HTML，再重新部署在线版本。

更换版式模板

  1. 准备新的唛头和入库单示例 DOCX。
  2. 使用 scripts/tokenize_templates.py 将示例数据替换成占位符。该步骤需要安装 python-docx。
  3. 覆盖 assets/唛头_模板.docx 和 assets/入库单_模板.docx。
  4. 运行 pdd_docs.py fill 生成一单进行验证，再运行 build_kanban.py 重建看板。
python scripts/tokenize_templates.py \
  --mark-src 唛头.docx --mark-out assets/唛头_模板.docx \
  --in-src 入库单.docx --in-out assets/入库单_模板.docx

占位符

{{仓库地址}} {{仓库编码}} {{订单号}} {{收件人}} {{联系电话}} {{箱号}} {{总箱数}} {{总数量}} {{SKU}} {{品名}}

模板要求：占位符必须在 word/document.xml 中保持为连续文本，不能拆在多个 <w:t> 节点之间。tokenize 脚本会合并段落中的 runs 来保证这一点。

常见问题

现象检查方法
提示缺少必填字段字段名是否与清单中的 9 个中文名称完全一致；文本输入中冒号支持全角和半角。
唛头箱号没有 01 / 02 / 03确认“总箱数”为整数，并且模板中的 {{箱号}} 占位符未被修改。
生成的 DOCX 打不开确认没有手动改动模板 XML；含特殊字符的字段值应由脚本负责转义。
看板里模板没有更新替换 assets/ 模板后重新运行 build_kanban.py。
